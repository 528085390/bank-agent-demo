# 模拟银行系统需求文档

版本：1.2（完整功能 Mock 版）  
日期：2026-09-20  
状态：首版范围与接口需求

## 1. 定位与原则

系统是一个用于 AI Agent 演示的模拟银行后端。目标是覆盖完整功能面，提供稳定的接口、固定的正确数据和可重复的演示结果；不接入真实银行、支付、短信、商户、征信或理财市场。

技术采用单服务 + PostgreSQL 16 + FastAPI/SQLAlchemy。业务逻辑保持轻量：不做真实认证、不做复杂风控、不做分布式调度、不做真实 MFA；先通过请求中的 `user_id`、固定测试用户和功能接口完成场景演示。生产安全能力不属于本版本目标。

## 2. 用户与数据范围

- 每个请求可传 `user_id`，缺省使用 `u_zhang`；服务只做基本的 ID 存在检查，不做登录、密码、JWT 或权限令牌。
- 资源归属校验暂不作为首版要求；接口返回数据以请求参数和固定种子为准，前端/Agent 负责选择正确用户和资源。
- 金额统一使用 CNY 整数分 `amount_minor`；数据库使用 BIGINT。接口返回统一 JSON。
- 所有写接口支持可选 `idempotent_key`，重复键直接返回第一次结果，避免演示时重复扣款。
- 转账、申购、赎回、订阅扣款等资金操作使用一个数据库事务；余额不足、对象不存在等基础错误仍返回明确错误。

## 3. 首版完整功能

### 3.1 账户与流水

- 查询用户账户列表、账户详情、余额、活期/定期分类。
- 查询账户或用户全部流水，支持分页、日期范围、交易类型和分类过滤。
- 余额由账户字段维护；每次资金操作同步写交易记录。定期账户首版可查询，可按固定规则模拟收益。

### 3.2 智能转账

- 按姓名、手机号、备注搜索联系人；结果返回候选用户和账户。
- 普通转账、跨账户转账、定时转账、取消定时转账。
- AA 收款：按人数拆分金额，生成多个待收款请求；收款/拒绝/过期状态均可模拟。
- 转账支持固定的 green/yellow/red 权限字段和确认状态，但首版不强制认证，接口可通过 `confirm=true`、`mfa_code` 字段演示状态变化。

### 3.3 账单与分析

- 月度账单、年度账单、消费分类统计。
- 自定义账单分析：日期、分类、关键词、金额范围。
- 异常交易识别：大额、高频小额、短时间重复交易；返回命中的流水 ID 和规则说明。

### 3.4 理财

- 理财产品列表、详情、推荐和对比。
- 申购、持仓查询、收益模拟、赎回。产品为固定种子，收益按 `expected_return * days / 365` 计算；不连接行情系统。
- 申购/赎回产生订单、持仓和资金流水；同一幂等键不重复执行。

### 3.5 卡片

- 卡片列表、详情、申请虚拟卡/实体卡、卡片额度调整。
- 单日/单月限额、商户黑名单配置。
- 挂失、解挂、冻结、解冻；状态直接落库，红色权限只作为返回字段和演示确认步骤。

### 3.6 订阅与代扣

- 订阅列表、详情、取消、暂停、恢复。
- 模拟到期扣款、续费提醒和自动续费；每个账期只生成一次扣款流水。

### 3.7 跨场景联动

- 生日联动：读取联系人生日，在生日前两天创建 mock 鲜花/蛋糕订单并扣款；订单、任务、交易状态可查询。
- 模拟时钟支持拨时间和运行到期任务；定时转账、订阅扣款、生日订单共用任务表。

### 3.8 安全、审计和幻觉防护

- 每个写操作记录请求、旧值、新值、结果、操作类型和决策字段。
- 接口返回明确业务状态和业务 ID；Agent 只能根据实际返回宣称成功。
- 查询参数使用参数化 SQL；对备注、关键词中的 SQL 或提示注入文本按普通数据处理。
- 支持连续失败计数和资金工具锁定状态的模拟接口，但不实现复杂风控模型。

## 4. 轻量业务规则

- 用户校验、JWT、真实 MFA 和权限阻断首版不实现；`permission_level`、`confirm_required`、`mfa_required` 只作为可观察字段。正确测试码为配置值，传任意非空数字也可通过模拟校验。
- 绿色查询直接返回；黄色/红色写接口先返回 `pending_confirmation`，**再次调用同一个写接口并带 `confirm=true`** 后执行。**没有独立的确认接口**——确认就是重放同一个写操作（见 `app/domain/risk.py`）。
- 资金写操作必须校验金额、余额、账户状态和幂等键；转账双方流水在同一事务写入。允许用固定测试用户跨用户演示，不要求真实账户授权。
- 定时任务创建时记录执行时间，资金可选择创建时预留或执行时检查；首版统一执行时检查余额，任务失败不重试。
- 模拟时钟只能向前拨；管理员或演示端调用运行接口触发到期任务，不使用常驻后台调度器。
- 余额、持仓、卡片、订阅和订单状态以数据库当前值为准；重置接口恢复固定种子。

## 5. 固定演示主路径

1. 张三搜索联系人“爱人”，按手机号/姓名选中账户并完成 200 元转账。
2. 创建第二天定时转账，拨钟并执行，查询任务和流水。
3. 为爱人创建生日鲜花订单，运行任务并查询 mock 订单。
4. 查询月度账单、消费分类和异常交易。
5. 查询理财产品，申购 1000 元，查看持仓和模拟收益，再赎回。
6. 查询卡片并冻结/解冻，修改限额。
7. 查看 Netflix 订阅，执行一次模拟代扣并取消后续续费。
8. 查询审计日志，展示每个操作的请求 ID 和业务 ID。

## 6. 验收要求

- 账户、转账、定时任务、AA、账单、理财、卡片、订阅、生日联动均有可调用接口和固定种子数据。
- 每类写操作至少能演示成功、余额不足/对象不存在、重复幂等键三种结果。
- 所有成功写操作返回明确业务 ID：`transaction_id`、`task_id`、`order_id`、`holding_id` 或 `subscription_id`。
- 模拟时钟、种子重置、任务运行和审计查询可重复执行。
- 启动后 1 分钟内可提供 PostgreSQL API；不依赖外部服务。

## 7. 暂不实现的重型能力

真实用户认证、真实 MFA、真实支付和清算、分布式锁、消息队列、复杂风控模型、真实理财行情、生产级权限系统、HA 集群和多进程调度不属于本版本。安全相关的接口只有 `GET /security/status` 与 `POST /security/reset-lock` 两个，没有 auth/MFA 接口需要"保留"。`mock_mfa_code` 配置项存在但未被读取，模拟校验接受任意数字串。
