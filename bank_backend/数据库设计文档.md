# 模拟银行系统数据库设计文档

版本：1.3（完整功能 Mock 版 + 理财子智能体支持）  
日期：2026-10-05  
数据库：PostgreSQL 16

> 1.3 变更：新增 `wealth_risk_assessments` 表与 `products.redeem_rule` 字段（迁移
> `0002_wealth_support`），并为理财验收提供专用演示数据（见 §6）。原有 17 张表结构不变。
> 卡片接入新增 `cards.freeze_reason` 与 `card_actions`，两条迁移通过 `0003_card_wealth_merge` 合并；业务表共 19 张。

## 1. 设计原则

- 覆盖需求中的全部功能实体和接口，业务规则保持轻量，适合单服务演示。
- 第一版不做认证、JWT、严格资源授权和真实 MFA。`user_id` 来自请求参数，缺省 `u_zhang`；数据库保留用户关系，应用只做基础存在检查。
- 金额统一 BIGINT 整数分，币种仅 CNY；时间使用 `TIMESTAMPTZ`。复杂 JSON 使用 JSONB 保存可变详情，查询字段保持结构化。
- 资金写操作在单个 PostgreSQL 事务中更新账户余额、业务订单和交易流水；不引入消息队列或分布式锁。
- 幂等键按用户和接口类型保存；重复请求返回原业务结果。

## 2. 核心表

### users

`id TEXT PK`、`name TEXT`、`phone TEXT UNIQUE`、`email TEXT`、`birthday DATE NULL`、`risk_level TEXT`、`status TEXT`、`created_at TIMESTAMPTZ`。

### accounts

`id TEXT PK`、`user_id TEXT FK users`、`account_type TEXT(current/fixed)`、`currency TEXT DEFAULT 'CNY'`、`balance_minor BIGINT`、`available_minor BIGINT`、`interest_rate NUMERIC(8,5)`、`status TEXT(active/closed)`、`created_at`。金额 CHECK >= 0；定期账户可查询但首版写操作可按接口规则拒绝。`available_minor` 是冗余读模型字段，每次资金事务必须与 `balance_minor` 一起更新，并在初始化、重置和健康检查中校验其值。

### cards

`id TEXT PK`、`user_id FK`、`account_id FK`、`card_number TEXT`（仅保存脱敏值）、`card_type TEXT(debit/credit/virtual)`、`expiry_date DATE`、`cvv_masked TEXT`、`daily_limit_minor BIGINT`、`monthly_limit_minor BIGINT`、`status TEXT(active/frozen/blocked)`、`merchant_blacklist JSONB`、`created_at`。

`0002_card_actions` 增加 `freeze_reason VARCHAR(16) NULL`：`manual` 表示临时冻结，`lost` 表示挂失。历史冻结卡为 NULL，按普通冻结处理。普通解冻不能解除挂失。

### card_actions

`id VARCHAR(64) PK`（公开业务引用 `CA-<uuid>`）、`user_id FK users`、`operation VARCHAR(32)`、`parameters JSONB`（不可变执行参数）、`before JSONB`（准备时卡片快照）、`permission_level VARCHAR(16)`（yellow/red）、`status VARCHAR(16)`（pending/authorized/cancelled/completed）、`verification_failures INTEGER CHECK >= 0`、`idempotency_key VARCHAR(128)`、`request_hash VARCHAR(64)`、`expires_at TIMESTAMPTZ`、`result JSONB NULL`、`created_at TIMESTAMPTZ`。

唯一键 `(user_id, idempotency_key)`；索引 `user_id`；用户外键 RESTRICT。有效期使用真实 UTC 时间十分钟，不随模拟时钟调整。授权和执行按记录加行锁；执行同时提交卡片/订单、完成记录与审计，重复执行只重放 result。验证码仅在请求时比较，不存入本表或审计。演示重置先删除本表，再删除卡片与用户。

### 银行卡交易密码（0004_card_transaction_password）

增量迁移的父版本为团队合并版本 `0003_card_wealth_merge`，不改写卡片、理财或其他模块迁移编号，不重置任何业务数据。

`cards` 增加以下银行私有字段：`transaction_password_hash VARCHAR(256) NULL`、`password_version INTEGER NOT NULL DEFAULT 0`、`password_failures INTEGER NOT NULL DEFAULT 0`、`password_code_failures INTEGER NOT NULL DEFAULT 0`、`password_locked_until TIMESTAMPTZ NULL`。使用标准库 scrypt（N=32768、r=8、p=3）与每次独立生成的 16 字节随机盐保存不可逆哈希；不保存明文或可逆密文。默认初始交易密码来自银行配置 `DEMO_CARD_PASSWORD`（演示默认 246810），迁移逐卡初始化现有空凭据，新申请卡通过 ORM 默认函数生成独立哈希；改变配置不覆盖已有密码。

`card_actions` 增加私有字段 `expected_password_version INTEGER NULL`、`pending_password_hash VARCHAR(256) NULL`。它们不进入通用 parameters、before、result、action_view、card_view 或审计。准备时记录版本，验证后只暂存新哈希；执行时锁定操作与卡片，比较版本并同时提交哈希更新、版本递增、完成状态和不含凭据的审计。重复执行返回已有结果；并发操作中只允许一个旧版本执行成功。

旧密码和验证码的失败次数跨操作按卡片累加；任一达到三次锁定十五分钟并取消当前操作。成功验证清零连续失败计数。取消、执行成功或访问已过期/已失效的操作时清除暂存哈希；闲置过期记录的私有哈希在后续访问时清理，不提供额外后台清理任务。SQLAlchemy 运行库与迁移连接隐藏绑定参数，避免异常日志输出哈希。

### contacts

`id TEXT PK`、`user_id FK`、`name TEXT`、`phone TEXT`、`remark TEXT`、`recipient_user_id FK users`、`recipient_account_id FK accounts`、`birthday DATE NULL`、`created_at`。姓名可重复，用于模糊匹配演示。

### transactions

`id TEXT PK`、`user_id FK`、`account_id FK`、`counterparty_account_id FK accounts NULL`、`direction TEXT(debit/credit)`、`amount_minor BIGINT`、`transaction_type TEXT(transfer/transfer_in/purchase/redeem/interest/subscription/aa/consumption/birthday)`、`category TEXT NULL`、`status TEXT(pending/completed/failed/cancelled)`、`remark TEXT`、`reference_type TEXT`、`reference_id TEXT`、`created_at TIMESTAMPTZ`、`updated_at`。

一笔双边资金操作可以生成两条 transaction，共享 `reference_id`；消费流水可只有付款方记录。索引 `(user_id, created_at DESC, transaction_type)`、`(account_id, created_at DESC)`。

### products

`id TEXT PK`、`name`、`product_type`、`min_amount_minor`、`max_amount_minor`、`expected_return NUMERIC(8,5)`、`risk_level`、`duration_months`、`redeem_rule TEXT(flexible/maturity_only)`、`status(available/sold_out)`、`created_at`。

`redeem_rule` 由 0002 迁移加入并按 `duration_months` 回填：0 个月为 flexible，正数为 maturity_only；库层有 CHECK 约束，非空。

### holdings

`id TEXT PK`、`user_id FK`、`product_id FK`、`source_account_id FK`、`principal_minor BIGINT`、`current_value_minor BIGINT`、`expected_return`、`purchased_at`、`maturity_date DATE NULL`、`status(holding/redeemed/partial)`、`created_at`。

接口返回的 `redeemable_minor` 与 `realized_income_minor` 是**派生字段**，不新增列：可赎回额按 `redeem_rule` 与到期日计算；已实现收益汇总本人该持仓已完成 `product_redeem` 订单 `details.interest_redeemed_minor`。持有收益沿用 `current_value_minor − principal_minor`，不另建收益账本。

### orders

统一记录理财、生日 mock 和卡片申请：`id TEXT PK`、`user_id FK`、`order_type TEXT(product_purchase/product_redeem/birthday/card_application)`、`product_id NULL`、`holding_id NULL`、`from_account_id NULL`、`to_account_id NULL`、`amount_minor BIGINT`、`status TEXT(pending/completed/failed/cancelled)`、`details JSONB`、`transaction_id NULL`、`created_at`、`updated_at`。

### scheduled_tasks

统一记录定时转账、生日任务和其他到期动作：`id TEXT PK`、`user_id FK`、`task_type TEXT(scheduled_transfer/birthday_order/subscription_charge)`、`execute_at TIMESTAMPTZ`、`payload JSONB`、`status TEXT(scheduled/running/completed/failed/cancelled/expired)`、`result JSONB NULL`、`error_code NULL`、`created_at`、`updated_at`。索引 `(status, execute_at)`。

### aa_requests

`id TEXT PK`、`user_id FK`、`from_account_id FK`、`total_amount_minor BIGINT`、`participant_count INT`、`remark`、`status TEXT(open/partial/completed/cancelled/expired)`、`created_at`、`expires_at`。

### aa_participants

`id TEXT PK`、`aa_request_id FK`、`position INT NOT NULL`（参与人在本次 AA 中的序号，接口对外叫 `participant_index`）、`name`、`phone`、`account_id FK NULL`、`amount_minor BIGINT`、`status TEXT(pending/paid/refused)`、`transaction_id NULL`、`paid_at NULL`。`UNIQUE(aa_request_id, id)`、`UNIQUE(aa_request_id, position)`。

### subscriptions

`id TEXT PK`、`user_id FK`、`from_account_id FK`、`name`、`merchant_name`、`amount_minor BIGINT`、`frequency TEXT(daily/weekly/monthly/yearly)`、`start_date DATE`、`next_due_date DATE`、`status TEXT(active/paused/cancelled)`、`auto_renew BOOLEAN`、`last_charge_id NULL`、`created_at`。

### subscription_charges

`id TEXT PK`、`subscription_id FK`、`due_date DATE`、`amount_minor BIGINT`、`transaction_id NULL`、`status TEXT(completed/failed)`、`created_at`、`UNIQUE(subscription_id, due_date)`。

### audit_logs

`id TEXT PK`、`request_id TEXT`、`user_id TEXT NULL`、`action TEXT`、`resource_type TEXT`、`resource_id TEXT`、`old_value JSONB`、`new_value JSONB`、`permission_level TEXT`、`confirm_required BOOLEAN`、`mfa_required BOOLEAN`、`result TEXT`、`reason TEXT`、`created_at TIMESTAMPTZ`。索引 `(user_id, created_at DESC)`、`(request_id)`。

### idempotency_records

`user_id TEXT`、`operation_type TEXT`、`idempotent_key TEXT`、`request_hash TEXT`、`result JSONB`、`created_at`，主键 `(user_id, operation_type, idempotent_key)`。

### simulation_state

单行表：`id INT PK CHECK(id=1)`、`current_time TIMESTAMPTZ`、`run_id UUID`、`updated_at`。管理员拨钟和运行任务使用该值。

### security_state

`id INT PK`、`user_id FK`、`tool_name`、`failure_count INT`、`locked_until TIMESTAMPTZ NULL`、`last_reason`、`updated_at`。仅用于模拟安全锁定状态。

### wealth_risk_assessments（0002 新增）

`id TEXT PK`、`user_id TEXT FK users ON DELETE RESTRICT`、`answers JSONB`、`score INT`、`risk_level TEXT(low/medium/high)`、`rule_version TEXT`、`assessed_at TIMESTAMPTZ`、`expires_at TIMESTAMPTZ`。索引 `(user_id, assessed_at DESC)`。

- 每次完成问卷**追加一条**，不覆盖历史；`answers` 保存 `q1..q5` 到 0/1/2 的原始答案。
- `score` 与 `risk_level` 由服务端按 `wealth-risk-v1` 计算，CHECK 约束限定 `score` 在 0..10、等级在 low/medium/high；客户端不能指定最终等级。
- 有效期 30 天，`valid` 由银行模拟时钟派生；过期记录保留，不用删除表示过期。
- 删除顺序：`seed/reset` 在删除 `users` 之前先删除本表（外键 RESTRICT）。

## 4. 轻量事务规则

1. 资金操作开始事务，按 ID 查询并更新账户余额。
2. 校验金额为正整数、账户状态 active、余额足够；失败回滚并写失败审计。
3. 写业务订单/持仓/订阅扣款记录和一条或两条 transactions。
4. 写成功审计和幂等结果后提交。重复幂等键直接返回保存结果。
5. 定时任务由 `/clock/run-tasks` 查询 `execute_at <= current_time` 且 status=scheduled 的记录，逐条执行并更新状态。
6. 理财收益、订阅下一扣款日、生日商品价格均为应用层固定规则，不引入外部服务。

### 理财写入口的事务顺序（0002 起）

申购／赎回在外层事务里按固定顺序执行，规则只作用于理财，不改动转账等其他域：

```text
锁定当前用户行（串行化同一用户的理财写）
→ 校验金额、计算业务指纹
→ 查 (user_id, operation_type, idempotent_key)：命中且指纹相同返回原回执；指纹不同拒绝
→ 检查安全锁定、账户／持仓归属、产品可售、金额上下限、有效测评与风险匹配、赎回规则与到期日
→ 校验 confirm 与演示验证码
→ accounts 减／增余额、holdings 变动、orders、transactions、audit_logs
→ 同一事务写 idempotency_records（含业务指纹）并提交
```

正常重复在资金修改之前返回，因此首笔已改变余额或全部赎回后，同键重放仍返回原回执。
失败时资金、持仓、订单和幂等结果整体回滚；失败审计与安全计数在独立事务保留。

## 5. PostgreSQL 初始化与迁移

- 使用 PostgreSQL 16 数据库 `bank_db`，连接账号取自仓库根目录已提交的 `database.txt`（当前为 `root01`）。2026-09-20 更名：原库名 `bank_agent_db`、原角色 `bank_agent`；2026-09-21 起默认连接账号改为 `root01`（`bank` 角色仍在，但默认配置不再引用它）。
- 使用 Alembic 管理 schema；初始化顺序为建表、外键/索引、固定种子、对账检查。
- 迁移图：`0001_bank_mock_domain` 分为 `0002_wealth_support` 与 `0002_card_actions`，再合并为 `0003_card_wealth_merge`。理财分支给 `products` 加 `redeem_rule` 并新建 `wealth_risk_assessments`，卡片分支新增冻结原因及操作记录；合并节点不改业务结构。两条已部署分支升级时保留已有数据，完整降级会反向删除两个分支新增的结构。
- 所有外键使用 `ON DELETE RESTRICT`；演示重置通过事务按依赖顺序清空业务数据并重新插入种子，不删除 schema。删除顺序已包含 `wealth_risk_assessments`（在 `users` 之前）。
- 初始化检查：账户余额非负、所有持仓和订单引用有效、订阅账期唯一、幂等键唯一（这四项由 CHECK 约束、RESTRICT 外键或 UNIQUE 约束在库层保证）。**AA 参与者金额总和等于总额不在初始化时校验**，它由 `aa_service.py` 构造时保证，并有一个单元测试断言。
- 不要求分区、读写分离、HA、消息队列或常驻调度器；这些不影响本 mock 的接口和数据完整性。
