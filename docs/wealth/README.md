## 范围提醒

本轮整改已在本地 `dev` 上实施（基线 `50e6f7e`，包含远端 `b907542`）：整轮调用链接通，
模型按工具表自主选择工具与自由追问，外层统一管理会话上下文，理财接收受控确认事件。
**C1（前端 → 主助手的可信按钮事件通道）已解除**：预览经 SSE `interrupt`（`kind=confirmation`）
送到页面，点击经鉴权路由 `POST /api/conversations/{id}/pending-actions/{pending_id}/decide`
回到理财，待办不再被撤下。
**D2（银行要求验证码）已按"确认框变形"解决**：适配器如实声明 `CLICK_AND_CODE`，确认框因此出现
验证码输入，用户在框里当场输入，运行时把它原样提交给银行——**没有改银行，也没有代填任何码**。
银行将来提供无验证码通道时，把 `write_authorization()` 改成回答 `CLICK` 即可，卡片与前端都不用动。

复核轮次另外修掉了一个资金安全缺陷：一次写请求**结果未知**时不再被外层折叠成"失败"，而是走
`TurnStatus.UNKNOWN`（细节与残留限制见验收记录 1.7 P1-a）。

银行侧数据、收益率和验证码全部是模拟值，不构成真实金融认证或收益承诺。
