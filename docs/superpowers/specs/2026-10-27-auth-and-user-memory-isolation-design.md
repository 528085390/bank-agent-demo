## 2. 目标和已确认产品选择

必须支持注册、登录、退出、修改密码；重新登录后能找回自己的历史。A/B 的对话、摘要、银行账户、账单、报告与审计隔离；多个设备登录同一用户可读取本人历史。身份由服务端解析，不能由前端或模型指定。

用户已于 2026-10-27 明确确认以下首版范围：

| 决策 | 已确认方案 | 首版边界 |
| --- | --- | --- |
| 登录标识 | 用户名 + 密码 | 不做手机号、短信或邮箱登录 |
| 新用户银行数据 | 自动创建独享模拟客户和独立演示数据 | 无需手动绑定；不共用固定演示客户和私有业务记录 |
| 记忆范围 | 每个对话独立，**不做跨对话偏好**（2026-10-28 变更） | 不自动从聊天提取长期记忆，也不提供手动保存入口；历史不跨对话检索 |
| 密码找回 | 首版不做自助找回 | 不增加恢复邮箱、恢复令牌或找回接口；仍支持验证旧密码后改密 |

前三项由用户于 2026-10-27 确认；第四项（记忆范围）于 2026-10-28 改为「不做跨对话偏好」，理由见文首变更说明。后文的技术与交互细节是据此提出的设计。注册页面明确提示首版暂无自助找回，避免用户误以为填写账单收件邮箱就能找回密码。

### 2.1 用户可感知的流程

1. 注册：填写登录名、密码和确认密码，注册完成后进入登录页；后台为本人自动准备模拟银行数据。
2. 首次登录：仅加载本人资料、会话和银行准备状态；准备中不能调用银行工具，可查看进度。失败显示重试入口，重试复用同一初始化任务。
3. 对话：创建会话 A 后说明预算，继续 A 可以记住；新建会话 B 默认不知道 A 的内容。同一账号重新登录仍能打开 A。
4. 偏好：**本版不做**。没有「我的偏好」页面，也没有跨对话注入；用户在某个对话里提出的语言、称呼等要求只对那个对话生效，新建会话即失效。
5. 管理记忆：**本版不做**。页面不提供偏好列表、修改或删除入口；不存在的记忆不需要管理，也就没有「删了还注入」这类问题。
6. 切换账号：先退出 A，再登录 B，页面不显示 A 的消息、报告和草稿；B 也不能通过修改资源 ID 访问 A 的内容。

## 3. 技术路线

| 路线 | 适配与代价 | 建议 |
| --- | --- | --- |
| 应用身份服务 + 数据库登录态 + HttpOnly Cookie | 复用当前同源请求和会话表，易于撤销登录，改动集中 | **首选** |
| JWT access/refresh 双令牌 | 需轮换、重放检测和撤销机制，仍不解决数据归属问题 | 暂不引入 |
| 独立身份服务/SSO | 适合后续真实银行统一身份，当前增加部署运维 | 保留适配边界 |

实施时须按锁定依赖版本核实框架、密码库文档；本草案不指定未经核实的 SDK 语法。

## 4. 账号、登录态、对话、记忆的边界

```text
app_user.user_id（稳定用户身份）
  ├─ auth_credential（登录凭据）
  ├─ LoginSession × N（设备登录，可过期/撤销）
  ├─ Conversation × N（本人聊天）
  │    ├─ conversation_message（历史）
  │    ├─ context_summary（本对话摘要）
  │    └─ 已存 thread_id → checkpoint / domain_context / pending action
  └─ bank_customer_id（服务端建立的一对一银行客户绑定）
```

登录态与聊天是两种对象。退出撤销登录，不删除历史；记忆只归具体对话，不归临时登录 token，也不跨对话共享。沿用现有已存 `thread_id`，不重命名历史检查点。thread 是状态定位键，不是授权凭证：先校验对话归属，再从数据库取 thread。

同一用户跨设备可读历史；资金待确认卡如绑定旧登录会话，重新登录或换设备必须重新预览确认，不能沿用旧授权。

## 5. 常规注册登录规划

### 5.1 注册与账号

- 页面只有登录名、密码、确认密码及协议确认，不要求手机号或邮箱。**一个账号只有一个名字，就是登录名**：不再有独立的显示名字段，避免同一个用户在两处叫法不同。服务端生成 `user_id`，不接受客户端指定角色或银行客户号。
- 登录名采用明确归一化规则、数据库唯一约束，处理并发重名；限字母、数字、下划线。
- 建议密码长度 15–128 字符，允许粘贴，不裁剪或截断。成熟密码库使用 Argon2id、随机盐，参数按服务器实测并在实施时核实。
- 密码、验证码和登录 token 不进 Prompt、消息账本、日志或审计载荷。注册成功跳转登录；客户初始化未完成时显示准备中，银行操作失败关闭。

### 5.2 登录、续期与退出

- 登录生成高熵随机 token，仅通过 HttpOnly Cookie 返回，库内存摘要；内部 `session_id` 保留给现有外键和追踪，不能再直接作为浏览器认证凭证。
- 登录签发新 token；旧演示会话、URL 参数和 `X-Session-Id` 不得绕过真实鉴权。测试身份替身通过测试依赖注入提供。
- 建议空闲超时 30 分钟、绝对有效期 24 小时，首版不提供永久登录；鉴权时间始终使用真实墙钟，不使用模拟银行时钟。
- Cookie 配置 HttpOnly、SameSite 和明确 Path；外网账号发布使用 HTTPS + Secure。所有修改类请求验证可信 Origin，登录后另带与登录态绑定的 CSRF token，登录和注册同样防跨站提交。
- 登录失败使用一致文案；按账号和可信客户端 IP 组合限速，状态共享/持久化，不以单进程内存作为唯一防线。
- 当前退出及全部设备退出都先持久化撤销，再清 Cookie 和前端状态。第一版移除 `Identity._cache` 的直接鉴权放行，每次请求查登录态和账号状态；后续缓存优化必须支持跨 worker 撤销。

### 5.3 改密与找回

- 改密验证当前密码，完成后撤销旧登录态，重新登录。登录不代替交易确认与银行 MFA。
- 首版不提供自助找回入口、恢复邮箱验证、恢复令牌表或找回接口，不纳入本轮实现和验收。
- 当前报告收件邮箱 `AppUser.email` 继续仅用于业务报告，不能拿来找回密码；不能仅凭用户号重置密码。
- 未来如单独增加找回功能，需另行设计经过验证的恢复渠道、令牌有效期与原子一次性消费；不在本轮顺带实现。

## 6. 增量数据模型与接口

| 对象 | 拟增内容 |
| --- | --- |
| `app_user` | 账号状态、普通用户/管理员角色、创建/更新时间；管理员由受控运维初始化 |
| `auth_credential` 新表 | 用户、唯一归一化登录名、密码摘要、密码更新时间 |
| 现有 `session` | token 摘要、最近活动时间、撤销时间、绝对到期；保留内部 session ID 与外键 |
| 客户初始化任务 | 用户、幂等键、状态、错误及重试信息，与注册用户同库提交 |
| 用户报告产物 | 用户、对话、锚点消息、报告 ID、内容或存储引用；先复用现有服务端能力，补足缺失部分 |

消息和摘要可沿用 Conversation 外键表达归属，不必机械重复增加用户字段；所有读取入口须验证所有权。

拟定接口：`POST /api/auth/register`、`POST /api/auth/login`、`GET /api/auth/me`、`POST /api/auth/logout`、`POST /api/auth/logout-all`、`POST /api/auth/password/change`；另提供登录态绑定的 CSRF token 及本人银行准备状态查询。首版不开放密码找回或重置接口，也不开放偏好管理接口（P4 已取消）。

沿用现有响应信封、错误码与 request_id；响应不暴露密码摘要或认证 token。`GET /api/session` 可短期作真实鉴权的兼容视图；无凭据领取固定身份的 `POST /api/session` 在多用户模式关闭。

## 7. 全链路隔离

### 7.1 服务端数据和上下文

可信链路：Cookie → 有效登录态和账号状态 → 用户 → owned conversation → 已存 thread → 记忆/领域状态 → 绑定客户的工具。body、query 或模型参数中的用户号、客户号、thread 均不能改变执行身份。

复用 `ConversationService._owned_in` 和 404 语义；覆盖详情、消息分页、修改、归档、删除/恢复、发送/重试、确认卡、任务图、审计、账单任务、附件下载、报告、收件人设置。不能只保护聊天主入口。

当前 `read_ledger()`、摘要和 `ContextAssembler.assemble()` 主要接收对话 ID，依赖外层归属检查。多用户演进时传入可信对话范围对象或明确的用户范围，在服务边界验证所有权。后台标题、摘要、邮件与报表任务也须显式携带归属，不能继承其他请求残留状态。

### 7.2 记忆范围

- 历史、摘要和领域状态只恢复到同一对话；同用户另一对话不自动继承预算、未完成交易或任何偏好。
- **本版不做跨对话记忆**（2026-10-28 变更）。既不做自动提取，也不做手动保存入口，也没有偏好表与偏好接口。
- 用户在聊天里提出的语言、称呼、展示要求只对当前对话生效。它留在该对话的账本与检查点里，新建会话不继承，同用户另一个对话也不继承 —— 这是 P1–P3 的隔离目标，不是缺陷。
- 风险承受能力、余额、持仓等业务事实以银行为准；任何对话内记忆都不提供实时余额，也不构成系统指令或权限。
- 对话内记忆同样不存密码、验证码、完整卡号、确认状态、一次性授权、幂等键或可直接恢复资金执行的指令；这些由既有脱敏与契约约束保证。
- 记忆的删除对象只有原始聊天历史：删除会话即删除该对话的账本与摘要。因为不存在跨对话偏好行，「删了偏好但原话还在」这种不一致在本版不会出现。

### 7.3 前端账号切换

- 统一账号状态管理；鉴权完成前不恢复会话/报告，401 不自动领取演示用户。
- 退出或切换清空列表、消息、报告、上传状态、邮箱、草稿、验证码、任务图、演示状态，补齐 `resetSessions()`、`resetCache()` 等清理入口。
- 默认停止在 localStorage 持久化消息和报告正文，报告迁到服务端经归属校验读取。最近会话等非敏感偏好可按用户分键；仅给敏感正文加用户前缀不能形成同源数据安全边界。
- 升级时登录前清理旧版待提交正文和报告键，禁止自动迁给新账号；旧报告如服务端无副本，需要重新生成。
- SSE、上传、轮询、普通请求支持取消；身份改变时取消旧请求。回调携带身份世代编号，过期世代不得写页面，阻止 A 的迟到响应落入 B 的界面。
- 多标签页同步退出/身份变化并清理；重新聚焦复核身份。敏感响应 `Cache-Control: no-store`。同浏览器多个标签页默认共用 Cookie/同一用户，同时登录两个账号使用独立浏览器配置或隐私窗口。

### 7.4 银行身份和管理面

- 新账号与模拟客户一对一绑定；禁止客户端任意认领客户号、统一绑定 `u_wealth` 或缺号回落到 `u_zhang`。
- 按用户幂等 provision 是首版必需能力：注册事务记录初始化任务 → 银行自身事务创建客户和独立样例 → 应用核对并提交绑定。跨两库无隐含原子事务，失败可查询和重试，不重复创建客户/余额。
- 初始化状态区分 `pending`、`processing`、`ready`、`failed`，有任务领取和超时恢复机制；进程重启后可继续处理。失败保留账号，通过受限的本人重试入口重新排队；不能要求用户反复注册，也不能将未就绪用户绑定到共享演示客户。
- 首版使用版本化的统一演示模板，覆盖账户/样例流水、卡、联系人、订阅、理财持仓与测评、生日场景；每位用户初始样例可相同，但私有记录 ID 和业务状态独立。只复制固定模板，不复制 `u_wealth` 等运行中客户已变化的余额或记录。
- 私有客户、账户、卡、联系人、订阅、持仓、任务、订单、流水、安全状态和业务幂等均重新生成 ID 并归属该客户；公共产品目录可共享。不能复制固定 ID 或调用全库 reset，仍遵守银行记账约束。
- 银行限制服务端访问并增加服务凭证；客户级接口强制明确身份并校验业务对象归属。服务凭证只能证明后端来源，不能代替最终用户和资源归属校验。
- 全局模型配置、时钟、跑批、清库、全局队列统计及安全解锁分别限制到管理员或本人资源。普通用户不能影响其他客户；共享模拟时钟只允许管理员推进，并说明其全局影响。
- 银行健康检查与固定种子余额解耦，另设最小就绪检查，避免正常交易/新客户触发错误判定。全库 reset 仅留受控运维，不进入注册、登录或日常发版流程。

### 7.5 退出和进行中的交易

撤销后新请求立即拒绝；长运行任务进入资金写门面前再检查登录态/权限。断开 SSE 不表示银行交易回滚。

资金写须明确受理边界并以并发控制固定顺序：撤销前已受理的写可能完成并保留回执；撤销后不得受理新写。结果未知沿用待核实流程，不自动重复扣款。已授权的未来定时业务不依赖浏览器持续登录；取消业务授权另走明确流程。

## 8. 迁移和发布

1. 增量加凭据、账号状态、token 摘要与撤销字段，保留用户 ID、对话、thread 和历史外键；备份后先加字段再切读写。
2. `user_0001` 的共享演示历史不归首位注册者、不复制给新用户；保留为受控演示档案。若继续登录演示账号，必须由运维设置新凭据；管理员单独初始化。
3. 首次切换撤销旧演示登录态、清缓存，保留旧 session 行以满足历史外键，不整表删除。
4. 收敛按用户初始化、种子、重置和健康检查；发布不得全库清空。
5. 当前外网是 HTTP 且 `COOKIE_SECURE=false`，账号对外验收需增加 HTTPS 终止并开启 Secure；遵守现有部署不能占用 443 的约束，具体入口实施前确定。
6. 原 Basic Auth 可暂留外层门禁，真实账号、限速与权限验收后再决定去留；它不算应用登录。
7. 回滚不清用户数据、不恢复无认证演示旁路；只回到同样要求真实登录的兼容版本，或进入维护模式。
